# 幸运抽奖功能 · 改造与接口对接文档（wxstore v1.6.0）

> 适用项目：wxstore（今华有小程序商城，生产 jar 部署）
> 功能来源：FengLing 积木 `fengling-lucky`（抽奖积木）移植
> 本文档用途：**给前端比对的改造说明 + 接口契约**（路径/字段/响应/错误码与积木版对齐，仅错误码段不同）
> 生成日期：2026-09-04

---

## 一、改造说明（后端做了什么）

### 1.1 功能范围
在 wxstore 新增 **幸运抽奖** 完整模块，覆盖：

| 能力 | 说明 |
|---|---|
| 活动管理 | 创建/更新/删除/启停，起止时间窗口 |
| 奖品配置 | 名称/图片/等级/**中奖概率（百分比，所有奖品含"谢谢参与"相加=100）**/总库存/剩余库存/排序 |
| 抽奖次数 | 每人**每日次数** / **总次数**限制（null=不限），有效抽奖（含未中奖/内定）都消耗 |
| 内定名单 | 后台指定"某用户必中某奖品"，命中后置 USED，之后恢复普通概率 |
| 抽奖算法 | 内定优先 → 按概率随机（只从剩余库存>0 奖品中抽）→ 原子扣库存 |
| 中奖记录 | `lucky_record` 落库，含奖品快照 + 8 位核销码 + 核销状态 |
| 自提核销 | 中奖后到店出示核销码，B 端凭码核销（WON → VERIFIED） |

> **概率规则（重要）**：奖品中奖概率用**百分比（`probability` 字段，0~100）**，**所有奖品（含"谢谢参与"格）概率相加必须等于 100%**。不用权重加权。抽奖时按概率随机；「谢谢参与」同样占概率百分比。内定名单命中不受概率约束（必中），但仍是有效抽奖、消耗次数。
> 校验（前后端都做）：1) 每个 `probability` ∈ [0,100]；2) 所有奖品 `probability` 总和 = 100；3) `probability`/`stock` 不能为负。任一不满足返回 8813。

### 1.2 与 FengLing 积木版的差异（前端比对重点）

| 对比项 | 积木版 | wxstore 版 |
|---|---|---|
| 接口路径 | `/api/lucky/**`、`/api/admin/lucky/**` | **完全一致** |
| 请求/响应字段 | 见下方接口契约 | **完全一致** |
| 错误码 | 15000~15049 | **8800~8833**（wxstore 统一错误码体系） |
| 奖品类型 type 字段 | 文档有、代码未落地 | **无**（全按实物自提处理） |
| 核销门店限制 | 无 | **无**（凭码即核销，不限门店） |
| 存储 | 内存版（重启丢失） | **MySQL 落库**（4 张新表） |

### 1.3 鉴权说明

| 接口 | 鉴权 | 说明 |
|---|---|---|
| `GET /api/lucky/config` | **匿名**（无需登录） | AuthInterceptor 白名单放行 |
| `POST /api/lucky/draw` | 需登录 | `Authorization: Bearer <userToken>`，userId 由后端从 JWT 取 |
| `GET /api/lucky/records` | 需登录 | 同上 |
| `/api/admin/lucky/**` | 需管理员登录 | `Authorization: Bearer <adminToken>`，**角色限 SUPER_ADMIN / ADMIN（商户管理员）** |

> 抽奖请求体**不传 userId**，后端从 JWT 解析，前端勿传（防止伪造他人抽奖）。

## 二、数据库变更（4 张新表）

执行本节 SQL 即可（已含在 `sql/add_lucky.sql`，可手动执行；线上库直接跑）。

```sql
-- =============================================================
-- 幸运抽奖模块（v1.6.0）· 4 张新表
-- =============================================================

-- 1. 抽奖活动表
CREATE TABLE IF NOT EXISTS `lucky_activity` (
  `id` bigint NOT NULL AUTO_INCREMENT COMMENT '活动ID',
  `name` varchar(64) NOT NULL COMMENT '活动名称',
  `description` varchar(255) DEFAULT NULL COMMENT '活动描述',
  `status` tinyint NOT NULL DEFAULT '0' COMMENT '状态：0=停用 1=启用',
  `start_time` datetime DEFAULT NULL COMMENT '活动开始时间',
  `end_time` datetime DEFAULT NULL COMMENT '活动结束时间',
  `daily_limit_per_user` int DEFAULT NULL COMMENT '每人每日抽奖次数限制（NULL=不限）',
  `total_limit_per_user` int DEFAULT NULL COMMENT '每人总抽奖次数限制（NULL=不限）',
  `create_time` datetime DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
  `update_time` datetime DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
  PRIMARY KEY (`id`),
  KEY `idx_status_time` (`status`, `start_time`, `end_time`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='幸运抽奖活动';

-- 2. 奖品表
CREATE TABLE IF NOT EXISTS `lucky_prize` (
  `id` bigint NOT NULL AUTO_INCREMENT COMMENT '奖品ID',
  `activity_id` bigint NOT NULL COMMENT '所属活动ID → lucky_activity.id',
  `name` varchar(64) NOT NULL COMMENT '奖品名称',
  `image` varchar(255) DEFAULT NULL COMMENT '奖品图片URL',
  `level` varchar(32) DEFAULT NULL COMMENT '奖项等级（如：一等奖/二等奖/谢谢参与）',
  `probability` int NOT NULL DEFAULT '0' COMMENT '中奖概率百分比（0~100，所有奖品含谢谢参与相加=100）',
  `stock` int NOT NULL DEFAULT '0' COMMENT '总库存',
  `remaining_stock` int NOT NULL DEFAULT '0' COMMENT '剩余库存',
  `sort_order` int NOT NULL DEFAULT '0' COMMENT '展示排序',
  `create_time` datetime DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
  PRIMARY KEY (`id`),
  KEY `idx_activity_id` (`activity_id`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='幸运抽奖奖品';

-- 3. 抽奖记录表
CREATE TABLE IF NOT EXISTS `lucky_record` (
  `id` bigint NOT NULL AUTO_INCREMENT COMMENT '记录ID',
  `activity_id` bigint NOT NULL COMMENT '活动ID → lucky_activity.id',
  `user_id` bigint NOT NULL COMMENT '用户ID → wx_user.id',
  `prize_id` bigint DEFAULT NULL COMMENT '奖品ID → lucky_prize.id（未中奖为 NULL）',
  `prize_name` varchar(64) DEFAULT NULL COMMENT '奖品名称快照（未中奖为 NULL）',
  `won` tinyint NOT NULL DEFAULT '0' COMMENT '是否中奖：0=未中奖 1=中奖',
  `verify_code` varchar(16) DEFAULT NULL COMMENT '核销码（中奖生成，自提核销用）',
  `status` varchar(16) DEFAULT NULL COMMENT '状态：WON=待核销 VERIFIED=已核销（未中奖为 NULL）',
  `verify_admin_id` bigint DEFAULT NULL COMMENT '核销管理员ID',
  `verify_time` datetime DEFAULT NULL COMMENT '核销时间',
  `create_time` datetime DEFAULT CURRENT_TIMESTAMP COMMENT '抽奖时间',
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_verify_code` (`verify_code`),
  KEY `idx_user_id_time` (`user_id`, `create_time`),
  KEY `idx_activity_id` (`activity_id`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='幸运抽奖记录';

-- 4. 内定名单表
CREATE TABLE IF NOT EXISTS `lucky_rigged` (
  `id` bigint NOT NULL AUTO_INCREMENT COMMENT '名单ID',
  `activity_id` bigint NOT NULL COMMENT '活动ID → lucky_activity.id',
  `user_id` bigint NOT NULL COMMENT '内定用户ID → wx_user.id',
  `prize_id` bigint NOT NULL COMMENT '内定奖品ID → lucky_prize.id',
  `status` varchar(16) NOT NULL DEFAULT 'UNUSED' COMMENT '状态：UNUSED=未发放 USED=已发放',
  `create_time` datetime DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
  PRIMARY KEY (`id`),
  KEY `idx_activity_user` (`activity_id`, `user_id`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='幸运抽奖内定名单';
```

## 三、C 端接口（微信小程序）

统一响应格式：`{ "code": 0, "message": "操作成功", "data": ... }`，`code=0` 成功，非 0 见错误码表。

### 3.1 抽奖配置（匿名）`GET /api/lucky/config`

无需登录。返回**当前启用且在时间窗口内**的活动 + 奖品展示（隐藏库存/权重）。无进行中活动时 `data` 为 `null`。

响应示例：
```json
{
  "code": 0,
  "message": "操作成功",
  "data": {
    "activityId": 1,
    "name": "开业大抽奖",
    "description": "全场消费满100元可抽奖一次",
    "startTime": "2026-09-01 00:00:00",
    "endTime": "2026-09-30 23:59:59",
    "dailyLimitPerUser": 1,
    "totalLimitPerUser": 3,
    "prizes": [
      { "prizeId": 1, "name": "免单券", "image": null, "level": "一等奖" }
    ]
  }
}
```

字段说明：

| 字段 | 类型 | 说明 |
|---|---|---|
| activityId | Long | 活动ID |
| name | String | 活动名称 |
| description | String | 活动描述（可空） |
| startTime / endTime | String | 活动起止时间（`yyyy-MM-dd HH:mm:ss`） |
| dailyLimitPerUser | Integer | 每人每日次数（null=不限） |
| totalLimitPerUser | Integer | 每人总次数（null=不限） |
| prizes[].prizeId | Long | 奖品ID |
| prizes[].name | String | 奖品名称 |
| prizes[].image | String | 奖品图片URL（可空） |
| prizes[].level | String | 奖项等级（如"一等奖"） |

### 3.2 抽奖（需登录）`POST /api/lucky/draw`

请求头：`Authorization: Bearer <token>`。请求体：**空**（不传任何参数，userId 后端从 JWT 取）。

规则：活动须启用且在时间窗口内；每日/总次数超限返回 8810/8811；内定名单用户必中；其余按奖品概率随机（含"谢谢参与"），中奖扣库存并返回核销码。

响应示例（中奖）：
```json
{
  "code": 0,
  "message": "操作成功",
  "data": {
    "won": true,
    "prizeId": 1,
    "prizeName": "免单券",
    "level": "一等奖",
    "verifyCode": "A1B2C3D4",
    "message": "恭喜中奖！"
  }
}
```

响应示例（未中奖）：
```json
{
  "code": 0,
  "message": "操作成功",
  "data": {
    "won": false,
    "prizeId": null,
    "prizeName": null,
    "level": null,
    "verifyCode": null,
    "message": "很遗憾，未中奖，感谢参与"
  }
}
```

| 字段 | 类型 | 说明 |
|---|---|---|
| won | Boolean | 是否中奖 |
| prizeId / prizeName / level | - | 中奖奖品信息（未中奖为 null） |
| verifyCode | String | **核销码（8 位大写字母数字），中奖后展示给用户，到店核销出示** |
| message | String | 提示文案 |

> 失败示例：`{"code":8810,"message":"今日抽奖次数已用完","data":null}`

### 3.3 我的抽奖记录（需登录）`GET /api/lucky/records`

请求头：`Authorization: Bearer <token>`。

| 参数 | 类型 | 默认 | 说明 |
|---|---|---|---|
| page | int | 1 | 页码 |
| pageSize | int | 10 | 每页条数 |

响应示例：
```json
{
  "code": 0,
  "message": "操作成功",
  "data": {
    "total": 2,
    "list": [
      {
        "id": 1,
        "activityId": 1,
        "activityName": "开业大抽奖",
        "won": true,
        "prizeName": "免单券",
        "level": "一等奖",
        "status": "WON",
        "verifyCode": "A1B2C3D4",
        "createTime": "2026-09-01 10:00:00"
      }
    ],
    "page": 1,
    "pageSize": 10
  }
}
```

| 字段 | 类型 | 说明 |
|---|---|---|
| id | Long | 记录ID |
| activityId / activityName | - | 所属活动 |
| won | Boolean | 是否中奖 |
| prizeName | String | 奖品名称（未中奖 null） |
| level | String | 奖项等级（未中奖 null） |
| status | String | **WON=待核销 / VERIFIED=已核销**（未中奖为 null） |
| verifyCode | String | 核销码（中奖展示，未中奖 null） |
| createTime | String | 抽奖时间（`yyyy-MM-dd HH:mm:ss`） |

## 四、B 端接口（管理后台）

请求头：`Authorization: Bearer <adminToken>`，角色限 **SUPER_ADMIN / ADMIN（商户管理员）**。

### 4.1 创建活动 `POST /api/admin/lucky/activities`

请求体：
```json
{
  "name": "开业大抽奖",
  "description": "全场消费满100元可抽奖一次",
  "status": 1,
  "startTime": "2026-09-01 00:00:00",
  "endTime": "2026-09-30 23:59:59",
  "dailyLimitPerUser": 1,
  "totalLimitPerUser": 3,
  "prizes": [
    { "name": "一等奖-免单券", "image": "https://cdn.example.com/1.jpg", "level": "一等奖", "probability": 5, "stock": 5, "sortOrder": 1 },
    { "name": "二等奖-小礼品", "image": null, "level": "二等奖", "probability": 15, "stock": 50, "sortOrder": 2 },
    { "name": "谢谢参与", "image": null, "level": "谢谢参与", "probability": 80, "stock": 9999, "sortOrder": 3 }
  ]
}
```

字段说明（LuckyActivityDTO）：

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| name | String | ✅ | 活动名称 |
| description | String | - | 活动描述 |
| status | Integer | ✅ | 0=停用 1=启用 |
| startTime | String | ✅ | 开始时间（`yyyy-MM-dd HH:mm:ss`） |
| endTime | String | ✅ | 结束时间 |
| dailyLimitPerUser | Integer | - | 每日次数（null=不限） |
| totalLimitPerUser | Integer | - | 总次数（null=不限） |
| prizes[].name | String | ✅ | 奖品名称 |
| prizes[].image | String | - | 奖品图片URL |
| prizes[].level | String | - | 奖项等级（如"一等奖"/"谢谢参与"） |
| prizes[].probability | Integer | ✅ | 中奖概率百分比（0~100，**所有奖品含"谢谢参与"相加须=100**） |
| prizes[].stock | Integer | ✅ | 总库存 |
| prizes[].sortOrder | Integer | - | 排序（越小越靠前） |

响应：`data` 为活动详情（见 4.5）。

### 4.2 更新活动 `PUT /api/admin/lucky/activities/{id}`

请求体同 4.1（整体覆盖活动字段 + 奖品列表；**同位置奖品保留剩余库存，新增奖品追加，被移除的奖品删除**）。

### 4.3 删除活动 `DELETE /api/admin/lucky/activities/{id}`

删除活动及其奖品/内定名单（**抽奖记录保留**）。

### 4.4 活动列表 `GET /api/admin/lucky/activities`

参数：`page`（默认1）、`pageSize`（默认20）。按创建倒序。响应 `data` 为 PageResult，`list[]` 元素见 4.5 活动详情。

### 4.5 活动详情 `GET /api/admin/lucky/activities/{id}`

```json
{
  "code": 0,
  "message": "操作成功",
  "data": {
    "id": 1,
    "name": "开业大抽奖",
    "description": "全场消费满100元可抽奖一次",
    "status": 1,
    "startTime": "2026-09-01 00:00:00",
    "endTime": "2026-09-30 23:59:59",
    "dailyLimitPerUser": 1,
    "totalLimitPerUser": 3,
    "prizes": [
      { "prizeId": 1, "name": "一等奖-免单券", "image": "https://cdn.example.com/1.jpg", "level": "一等奖" }
    ],
    "rigged": [
      { "userId": 1001, "prizeId": 1, "status": "UNUSED" }
    ],
    "createTime": "2026-09-01 09:00:00"
  }
}
```

### 4.6 启用/停用活动 `PUT /api/admin/lucky/activities/{id}/status?status=1`

`status=1` 启用，其余值停用。

### 4.7 配置抽奖次数 `PUT /api/admin/lucky/activities/{id}/times`

| 参数 | 类型 | 说明 |
|---|---|---|
| dailyLimitPerUser | Integer | 每日次数（不传或 null=不限） |
| totalLimitPerUser | Integer | 总次数（不传或 null=不限） |

### 4.8 设置内定名单 `PUT /api/admin/lucky/activities/{id}/rigged`

请求体（**整体覆盖**，重传即替换）：
```json
{
  "items": [
    { "userId": 1001, "prizeId": 1 },
    { "userId": 1002, "prizeId": 2 }
  ]
}
```

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| items[].userId | Long | ✅ | 内定用户ID |
| items[].prizeId | Long | ✅ | 内定奖品ID（须属于该活动） |

> 该用户下次抽奖时**必中**该奖品，命中后状态置 USED，之后恢复普通概率。每名用户一场活动最多必中一次。

### 4.9 内定名单查询 `GET /api/admin/lucky/rigged`

参数：`activityId`（可选，不传返回全部）。响应 `data` 为数组 `[{ "userId": 1001, "prizeId": 1, "status": "UNUSED" }]`。

### 4.10 抽奖记录列表 `GET /api/admin/lucky/records`

参数：`page`（默认1）、`pageSize`（默认50）。全部用户记录，按抽奖时间倒序。`list[]` 元素同 3.3 记录 VO。

### 4.11 自提核销 `POST /api/admin/lucky/verify`

请求体：
```json
{ "verifyCode": "A1B2C3D4" }
```

校验：核销码不存在 → 8832；未中奖记录 → 8831；已核销 → 8833。成功后该记录 `WON → VERIFIED`，记录核销管理员与时间。

## 五、错误码表（8800~8833）

| code | 含义 | 触发场景 |
|---|---|---|
| 8800 | 抽奖活动不存在 | 无进行中活动 / 活动已删 |
| 8801 | 抽奖活动未启用 | 活动被停用 |
| 8802 | 抽奖活动未开始 | 未到 startTime |
| 8803 | 抽奖活动已结束 | 已过 endTime |
| 8804 | 活动名称不能为空 | B 端创建/更新校验 |
| 8805 | 活动起止时间无效 | B 端创建/更新校验 |
| 8810 | 今日抽奖次数已用完 | 每日次数超限 |
| 8811 | 抽奖总次数已达上限 | 总次数超限 |
| 8812 | 奖品库存不足 | 并发扣减库存失败 |
| 8813 | 奖品配置无效 | 概率/库存为负，或概率总和≠100 |
| 8814 | 活动至少需要一个奖品 | prizes 为空 |
| 8815 | 内定名单用户无效 | 内定 userId 为空 |
| 8816 | 内定奖品不属于该活动 | prizeId 不属于该活动 |
| 8830 | 抽奖记录不存在 | （备用） |
| 8831 | 该记录未中奖，无需核销 | 核销未中奖记录 |
| 8832 | 核销码无效 | 核销码不存在 |
| 8833 | 该奖品已被核销 | 重复核销 |
