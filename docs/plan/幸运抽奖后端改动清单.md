# 幸运抽奖 · 后端改动清单（一次性完整）

> 生成日期：2026-09-04
> 用途：本文档把后端因「奖品概率由权重(weight)改为百分比(probability，总和=100)」需要改动的**所有**点一次性列清楚，供后端开发逐条落实。
> 权威契约：`docs/plan/幸运抽奖功能改造与接口对接文档.md`（已同步更新）。

---

## 一、核心变更（一句话）

奖品中奖概率从「权重加权」改为「**百分比**」：每个奖品填 `probability`（0~100），**所有奖品（含"谢谢参与"格）的 `probability` 相加必须等于 100**。抽奖按概率随机。

> 之前用 `weight`（越大越易中、无总和约束），现在**废除 `weight`，改用 `probability`**，并新增"总和=100"校验。

---

## 二、数据库变更（1 处）

`lucky_prize` 表：**`weight` 列改为 `probability`**。

```sql
-- 改列：weight → probability
ALTER TABLE `lucky_prize` CHANGE COLUMN `weight`
  `probability` int NOT NULL DEFAULT '0' COMMENT '中奖概率百分比（0~100，所有奖品含谢谢参与相加=100）';

-- 若列名已改为 probability，则只更新注释即可：
-- ALTER TABLE `lucky_prize` MODIFY COLUMN `probability` int NOT NULL DEFAULT '0' COMMENT '中奖概率百分比（0~100，所有奖品含谢谢参与相加=100）';
```

> 注意：若线上已有用 `weight` 的数据，需迁移为 `probability`（可先设 0，再由运营在后台重新配置为正确的 100% 总和）。

## 三、实体/DTO/字段变更

### 3.1 `LuckyPrize` 实体
- `weight` → `probability`（Integer，概率百分比）。

### 3.2 `LuckyPrizeDTO`（B 端创建/更新请求奖品项）
- 字段：`weight` → `probability`（必填，Integer）。
- 其余 `name / image / level / stock / sortOrder / prizeId` 不变。

### 3.3 `LuckyPrizeVO`（B 端详情/列表返回奖品项）
- **新增/替换**：`probability`（Integer）。
- 详情 4.5 的 `prizes[]` 需返回 `prizeId / name / image / level / probability`（前端编辑回显用）。

### 3.4 C 端 `config`（3.1）返回奖品项
- 按契约：`prizeId / name / image / level`，**不返回 `probability` / `stock`**（隐藏），保持现状即可（本来就没暴露 weight）。

## 四、校验规则（后端必须做）

保存活动（4.1 创建 / 4.2 更新）时，对 `prizes` 校验：

1. **每个 `probability`**：`0 <= probability <= 100`，且非负整数。
2. **总和 = 100**：`sum(prizes[].probability) == 100`（注意含"谢谢参与"格）。
3. **`stock` 不能为负**（原有）。
4. 任一项不满足 → 返回 **8813 奖品配置无效**（错误信息可附带具体原因，如"概率总和≠100"）。

> 说明：内定名单命中的奖品不受概率约束（必中），但仍消耗一次抽奖次数；内定名单**不参与**概率总和计算（内定是名单项，不在 prizes 里）。

---

## 五、抽奖算法变更

`POST /api/lucky/draw`（3.2）抽奖逻辑：

**原**：内定优先 → 加权随机（weight）→ 原子扣库存。

**改**：
1. 校验活动启用/时间/次数（8810/8811/8800~8803）不变。
2. 查当前用户内定名单：命中 → 直接指定奖品（**不受概率约束**，必中），否则继续。
3. 普通抽奖 → **按 `probability` 百分比随机**（含"谢谢参与"格），只从 `remaining_stock > 0` 的奖品中抽取。
4. 原子扣减库存（`remaining_stock--`）。
5. 生成 `lucky_record`（含奖品快照 + 8 位核销码 + `status=WON`）；未中奖 / 谢谢参与同样生成记录（`won=false` 或 `level=谢谢参与`，无核销码）。
6. **每次有效抽奖都消耗一次次数**（含未中奖/谢谢参与/内定）。

> 概率随机实现参考：`rand = random()*100`，遍历 prizes 累减 `probability`，落到哪个区间即中哪个。`谢谢参与` 是普通奖品格，同样按概率命中并扣库存。

## 六、接口契约同步（后端响应）

| 接口 | 需同步的点 |
|---|---|
| `POST /api/admin/lucky/activities`（4.1） | 请求体奖品项用 `probability`，校验总和=100 |

| `GET /api/lucky/records`（3.3） | 不变 |
| `POST /api/admin/lucky/verify`（4.11） | 不变 |

## 七、错误码变更

| code | 原 | 改 |
|---|---|---|
| 8813 | 奖品配置无效（权重/库存为负） | 奖品配置无效（**概率为负 / 概率超出0~100 / 概率总和≠100 / 库存为负**） |

其余错误码 8800~8816、8830~8833 不变。
