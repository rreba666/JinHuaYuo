# C 端用户输入约束设计

## 目标

为微信小程序 C 端所有用户可编辑字段增加一致的输入规范，减少空白、控制字符、格式错误和金额精度错误进入接口，同时不改变现有游客权限、实名前置、提现授权、订单和发票业务流程。

## 范围

本次只改 `mini_shop` C 端。B 端是管理者控制面，本次不改其业务规则；`staff-h5` 当前没有普通文本输入控件，也不增加无关表单。

覆盖字段：

- 商品搜索关键词
- 个人昵称
- 实名姓名、身份证号、银行卡号、银行预留手机号
- 配送联系人、自提联系人、地址变更联系人和地址
- 地址变更原因
- 发票个人抬头、公司抬头、纳税人识别号、邮箱
- 订单备注
- 提现金额、转账金额、接收人用户 ID

## 方案

新增 `mini_shop/utils/input-validation.ts` 作为纯函数校验工具。页面保留现有表单状态和接口调用，在以下两个位置接入：

1. 输入值进入表单或本地缓存时，执行轻量规范化，去除首尾空白、控制字符和零宽字符；数字类字段允许常见分隔空格在提交前被移除。
2. 所有提交、搜索和查询动作执行最终校验，校验失败只显示用户提示，不调用后端接口。

不做全局输入组件或请求拦截器，避免改变 UniApp 原生输入事件和现有页面交互。

## 规则

### 普通文本

- 去除首尾空白、C0/C1 控制字符和零宽字符。
- 保留中文、英文、数字、表情及常用标点，不限制为只允许中文。
- 必填字段禁止空字符串或纯空白。

字段长度：

| 字段 | 必填 | 最大长度 |
| --- | --- | ---: |
| 昵称 | 是 | 32 |
| 实名姓名 | 是 | 32 |
| 联系人姓名 | 是 | 32 |
| 公司名称 | 是（公司发票） | 100 |
| 配送/收货详细地址 | 是 | 200 |
| 地址修改原因 | 否 | 255 |
| 订单备注 | 否 | 100 |
| 搜索关键词 | 否 | 50 |

### 特殊字段

- 中国大陆手机号：严格匹配 `^1[3-9]\\d{9}$`。
- 身份证号：去除输入空白、末位转大写 `X`，校验 18 位格式、真实日期和身份证校验码。
- 银行卡号：去除输入空白和常见分隔符后只允许数字，长度 12-19 位；字段仍按后端定义保持可选。
- 银行预留手机号：字段非空时必须按手机号规则校验；字段仍按后端定义保持可选。
- 邮箱：非空且匹配常用邮箱格式，最大长度 254。
- 纳税人识别号：去除空白并转大写，只允许 15-20 位数字和大写字母，兼容常见旧税号和统一社会信用代码。
- 接收人用户 ID：只允许正整数，禁止小数、负数、科学计数法和空值。
- 提现/转账金额：必须是有限正数，最多两位小数；提现继续使用现有环境配置的最低金额和可用余额限制，转账继续使用现有最低金额和可用余额限制。

### 业务提交保持不变

- 实名认证仍只有 `certName` 和 `certNo` 为必填，银行卡和银行预留手机号不强行改为必填。
- 游客仍不能使用推广、钱包等受限功能。
- 提现仍先实名，再按零钱/银行卡的既有流程提交；零钱授权状态不改。
- 地址、发票、订单备注只在原有业务允许的页面提交。
- 后端错误仍按现有 `request`/`ApiRequestError` 流程展示，前端校验只负责拦截明显非法值。

## 页面接入

- `components/RealnameVerifySheet.vue`：实名四字段最终规范化和严格校验。
- `pages/mine/mine.vue`：昵称保存前清洗、长度和空值校验。
- `subpkg-goods/search/index.vue`：搜索词清洗、长度限制，空搜索按现有列表行为处理。
- `subpkg-order/payment/payment.vue`：配送地址、自提联系人、发票、备注和订单提交前统一校验；恢复表单缓存时清洗旧值。
- `subpkg-order/orders/detail.vue`：地址变更草稿恢复、输入和提交前统一校验。
- `subpkg-wallet/withdraw/withdraw.vue`：提现金额、转账金额和接收人 ID 使用专用规则，保留现有余额与实名授权流程。

## 错误处理

校验失败时使用现有 `uni.showToast({ icon: 'none' })`，提示具体字段和原因，例如“手机号格式不正确”“身份证号校验失败”“金额最多保留两位小数”。失败后不改变页面状态、不清除用户已填写的其他字段，也不发起接口请求。

## 测试策略

先为纯校验工具增加失败测试，再实现工具；覆盖：

- 控制字符和首尾空白清洗
- 合法/非法手机号
- 身份证日期和校验码
- 银行卡空格、非法字符和长度
- 邮箱、税号和正整数 ID
- 金额整数、两位小数、三位小数、负数、科学计数法和超余额
- 必填文本、长度上限和可选备注

随后执行小程序端可用的类型检查/构建、相关测试、`git diff --check`，并确认现有未提交业务修改未被覆盖。
