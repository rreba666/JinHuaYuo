## 一、后端（project-v1.4.0-prod，admin）
### ① 用户分红槽位 Tab
- `api/profit.ts`：`getAdminDividendSlots(userId?)` → `GET /api/admin/profit/slots`，返回 `List<DividendSlotEntity>`，`normalizeSlot` 转化 BIGINT/数值字段。
- `types/profit.ts`：新增 `AdminDividendSlot`（含 locked/invalidFlag/invalidReason/lockedAt 等）。
- `stores/profit.ts`：新增 `adminSlots` + `fetchAdminSlots(userId?)`。
- `views/profit/index.vue`：新增「用户分红槽位」Tab，按 userId 搜索（留空查全部）；展示槽位 ID/用户ID/订单号/商品/商品价/分红上限/累计分红/状态/锁死时间；`slotStatus`/`slotType` 区分「活跃 / 满额锁死(locked=1) / 退款作废(invalidFlag=1)」。

### ② 分红槽位数量配置 `dividend_slot_count`
- `api/setting.ts`：`getSlotCountConfig`/`saveSlotCountConfig` → 通用接口 `GET/POST /api/admin/setting/dividend_slot_count`（默认 3，body `{configValue, remark}`）。
- `types/setting.ts` 加 `SlotCountConfig`；`stores/setting.ts` 加 `slotCount` + `loadSlotCount`/`saveSlotCount`；`views/settings/index.vue` 加「分红槽位数量」配置卡（默认 3，整数 1~20）。

### ③ 每日红包 settled_flag 对齐
- `types/profit.ts` `SevenDayBonusDetail` 加 `cumulativeUserCount`/`settledFlag`/`settledAmount`。
- `api/profit.ts` `normalizeDetail` 解析新字段。
- `views/profit/index.vue`：未结算/已结算卡片「用户数/参与人数」改为「累计人数」（`cumulativeUserCount ?? dailyUserCount`）；已结算卡片新增「实发金额（settledAmount）」。
- **累计用户明细**：`api/profit.ts` 加 `getDailyUsers(asOfDate)`（`GET /api/admin/profit/daily/users/{asOfDate}`）；`types/profit.ts` 加 `DailyContributionUser`；`stores/profit.ts` 加 `dailyUsers` + `fetchDailyUsers`；已结算卡片新增「累计用户」操作列，点击弹窗展示该支付日累计用户贡献（用户ID/订单号/支付日/贡献金额/应急抽取/状态）。

## 二、C 端（mini_shop）
### 无槽位购买分红商品提示
- `subpkg-order/payment/payment.vue`：`submitPayment` 里，若订单含分红商品（`getDividendQuantity>0`），先调 `getDividendSlots()` 拿 `availablePurchase`；若 `availablePurchase < 分红商品数`，提示"您的分红槽位已满……"并拦截，不再发起下单。移除旧的硬编码 `> DIVIDEND_PURCHASE_LIMIT(3)` 判断（槽位上限现由后端 `dividend_slot_count` 配置控制）。
