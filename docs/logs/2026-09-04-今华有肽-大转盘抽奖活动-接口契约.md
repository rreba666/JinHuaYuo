# 今华有肽 大转盘抽奖活动 — 后端接口契约

> 关联工程：`E:\work\JJ\project`（今华有肽）。与 LonPin 无关。
> 日期：2026-09-04
> 本文档给后端团队实现接口参考，前端（mini_shop + admin）按此对接。

## 0. 通用约定

- 基础地址：`https://api.jinhuayou365.com`
- 统一响应包裹：
  ```jsonc
  { "code": 0, "message": "ok", "data": <T>, "success": true }
  ```
  - `code === 0` 且 `success !== false` 视为成功，`data` 为业务数据。
  - `code !== 0` 视为业务失败，`message` 提示给用户。
- 品牌隔离：请求头 `X-App-Key: jinhua`（当前品牌）。
- 鉴权：请求头 `Authorization: Bearer <token>`。小程序从 `uni.getStorageSync('mini_shop_token')` 取，admin 从登录态取。
- ID：int64 统一以 **字符串** 序列化（避免 JS 精度丢失）。
- 金额：数值（元，两位小数）。
- 时间：`yyyy-MM-dd HH:mm:ss` 字符串。
- 分页：`page`（1 起）、`pageSize`；返回 `{ total, list, page, pageSize }`。

## 1. 小程序端接口（用户态）

### 1.1 获取活动配置 `GET /api/lucky/config`

**说明**：返回当前活动配置与奖品列表；在登录态下附带该用户今日剩余次数。活动未配置或已停用仍返回结构（`enabled=0`），由前端提示。

**请求**：无 Body（需登录态以获得剩余次数；未登录可不带 token，返回 `remainCount` 为 0 或由前端引导登录）。

**响应 Data**：
```jsonc
{
  "id": "1",
  "enabled": 1,                    // 1=开启 0=关闭
  "startTime": "2026-09-04 00:00:00",
  "endTime": "2026-09-30 23:59:59",
  "dailyCount": 3,                 // 每人每日抽奖次数上限
  "remainCount": 2,                // 当前用户今日剩余次数（登录态计算；未登录=0）
  "rule": "活动规则文案（支持换行）",
  "prizes": [
    {
      "index": 0,                  // 格位索引（0 起，顺时针）
      "name": "一等奖",
      "image": "",                 // 奖品图片 URL（可空，前端用本地图或默认）
      "weight": 1,                 // 概率权重（仅配置用，前端展示不参与计算）
      "type": "REAL",              // REAL=实物 NONE=谢谢参与 INTEGRAL=积分 等
      "isDefault": false           // 是否谢谢参与兜底格
    }
  ]
}
```

> `prizes` 顺序即转盘格位顺序；数量由后端配置（如 6 / 8 格），前端按 `index` 渲染。

### 1.2 抽奖 `POST /api/lucky/draw`

**说明**：核心接口。后端校验活动开关、时间、登录态、剩余次数；按权重随机或按内定名单返回中奖结果。**中奖结果以本接口返回的 `prizeIndex` 为准，前端不做随机。**

**请求**：无 Body，空 JSON `{}`。

**响应 Data**：
```jsonc
{
  "prizeIndex": 1,                 // 命中的格位索引（驱动转盘动画指针角度）
  "prizeName": "谢谢参与",
  "prizeType": "NONE",
  "recordId": "100"                // 中奖记录 ID（字符串）
}
```

**业务失败错误码**：
| code | 场景 | 前端提示 |
| --- | --- | --- |
| `1001` | 活动未开启 | 活动暂未开始 |
| `1002` | 未到开始时间 / 已结束 | 活动未开始 / 活动已结束 |
| `1003` | 次数不足 | 今日抽奖次数已用完 |
| `1004` | 无权限（未登录/身份异常） | 请先登录 |
| `1005` | 内定名单外用户命中内定奖的概率已归零（兜底对齐，可复用作服务器内部错误） | 抽奖失败，请稍后重试 |

### 1.3 我的中奖记录 `GET /api/lucky/records`

**说明**：当前登录用户的中奖记录，分页，含"谢谢参与"（可按需过滤，由前端 `type` 判断是否展示）。

**请求**：Query `page`、`pageSize`。

**响应 Data**：
```jsonc
{
  "total": 1,
  "list": [
    {
      "id": "100",
      "prizeName": "一等奖",
      "prizeIndex": 0,
      "prizeType": "REAL",
      "status": "UNCLAIMED",       // UNCLAIMED=待领取 SHIPPED=已发奖 CLAIMED=已领取 等
      "createTime": "2026-09-04 12:30:00"
    }
  ],
  "page": 1,
  "pageSize": 10
}
```

## 2. 后台管理端接口（管理态）

> 前缀 `/api/admin`，需管理员 token；权限 `SUPER_ADMIN` + `ADMIN`。

### 2.1 查询活动配置 `GET /api/admin/lucky`

**响应 Data**：当前生效的活动配置，结构见 2.4；未配置时返回 `null` 或默认对象。

### 2.2 创建配置 `POST /api/admin/lucky`

**请求 Body**：见 2.4。创建成功返回 `data: { id: "1" }`。

### 2.3 更新配置 `PUT /api/admin/lucky/{id}`

**请求 Body**：见 2.4（完整替换活动下所有字段；奖品列表整体覆盖）。

### 2.4 配置数据结构（admin 保存用）

```jsonc
{
  "name": "大转盘活动",           // 活动名称
  "enabled": 1,                    // 1=开启 0=关闭
  "startTime": "2026-09-04 00:00:00",
  "endTime": "2026-09-30 23:59:59",
  "dailyCount": 3,                 // 每人每日抽奖次数上限
  "rule": "活动规则文案",
  "prizes": [
    {
      "index": 0,
      "name": "一等奖",
      "image": "https://...",
      "weight": 1,
      "type": "REAL",
      "isDefault": false,
      "designated": false,         // 是否内定（命中内定名单的用户必中该奖）
      "designatedUsers": []        // 内定用户清单（预留：用户ID/手机号 列表；为空则不启用内定）
    }
  ]
}
```

### 2.5 启停开关 `PUT /api/admin/lucky/{id}/status`

**请求 Body**：`{ "enabled": 0 }`。用于快速开启/关闭，无需整体保存。

## 3. 字段枚举约定

- `prize.type`：`REAL`（实物），`INTEGRAL`（积分），`COUPON`（优惠券），`NONE`（谢谢参与/空白）。前端按 `type` 做差异化展示。
- `record.status`：`UNCLAIMED`（待领取），`CLAIMED`（已领取），`SHIPPED`（已发奖），`EXPIRE`（已过期）等，前端按需展示。

## 4. 前端对接备注

- **mini_shop**：`api/lucky.ts` 封装 `getLuckyConfig` / `drawLucky` / `getLuckyRecords`，并按 `request` 统一错误处理（`code !== 0` 抛 `ApiRequestError`）。
- **admin**：`api/lucky.ts` 封装管理端接口，沿用 `request.get/post/put` + `unwrap` 模式。
