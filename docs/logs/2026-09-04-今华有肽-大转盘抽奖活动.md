## 关键实现要点

- **Vue3 适配**：官方 `@lucky-canvas/uni` 是 Vue2 Options API 写法，已重写为 `<script setup>` + TS。传入核心 `LuckyWheel` 第二个参数 `{ width, height, prizes, buttons, start, end }`，核心用 `flag: 'MP-WX'` 分支适配微信小程序 canvas（canvas 由组件 `createSelectorQuery().fields({node,size})` 获取，`ctx.scale(dpr)`）。
- **抽奖流程**：点中心按钮 → 组件 emit `@start` → 父页面 `play()` 让转盘转 → 拿后端/mock 返回的 `prizeIndex` → `stop(index)` 停在指定格 → `@end` 弹提示。结果以服务端（或 mock）`prizeIndex` 为准，前端不做随机。
- **mock 切换**：`index.vue` 里 `const useMock = true`。后端就绪后把 `useMock` 改为 `false`，即走 `getLuckyConfig`/`drawLucky`/`getLuckyRecords` 真实接口。

## 已知风险

- **lucky-canvas 核心 ESM 含 `window`/`document` 引用**：核心在 Web DOM 分支（`new Image()`、`document.createElement`）只有当 `flag` 为非小程序时才走；小程序路径用 `flag='MP-WX'` 规避。若真机报 `window`/`document is not defined`，需确认核心确实以 `flag='MP-WX'` 初始化。
- **canvas 指针/穿层**：中心按钮是叠加在 canvas 上的 `view`（`z-index:1`，canvas `pointer-events:none`）。若真机点不中，改用 `cover-view` 或调整层级。
- **转盘方向/格位对齐**：`stop(index)` 的格位索引与 `prizes[]` 的 `index` 对应关系需真机核对（0 起顺时针）。若停止格与其索引偏差，调整 `LuckyWheel` 的 `defaultConfig.offsetDegree`。
