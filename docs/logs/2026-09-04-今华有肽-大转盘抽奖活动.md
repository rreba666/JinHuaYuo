## 方案变更记录（重要）

- **初版（commit e86b038）**：使用 lucky-canvas 官方 uni 包装（`lucky-canvas@1.7.27` ESM 核心 + Vue 适配组件）。**问题**：核心 `lucky-canvas.js` 是压缩 ESM 单行文件（`export{...}`），uni 小程序编译器（`uni:mp-inject`）解析失败，报错 `Expected ',', got 'hidden'`。
- **替代方案考察**：`@lucky-canvas/mini@0.0.7` 是微信小程序原生组件（`component:true` + wxml/wxss），可在小程序编译，但接口是微信原生形式（`bindstart`/`bindend`），老版本 0.0.7，与 uni Vue3 集成有摩擦。
- **最终方案（commit b966613）**：**放弃 lucky-canvas，改为自研大转盘组件**（微信 2D canvas 自绘圆盘 + 转动动画）。复用项目 `PromotionCodePoster.vue` 的 canvas 经验（`createSelectorQuery().fields({node,size})` 拿 node，`ctx.scale(dpr)`）。无第三方兼容问题，样式/格位/动画/概率完全可控。

## 关键实现要点

- **自研大转盘**：用微信 2D canvas（`canvas type="2d"`）自绘圆盘——按 `prizes` 数量分扇区，每格背景色 + 奖品文字；顶部固定指针。转动用 `setTimeout` 驱动角度插值（`easeOutQuad` 缓动），`play()` 启动随机转、`stop(index)` 精确停在指定格，动画结束 `emit('end', index)`。
- **抽奖流程**：点中心按钮 → 组件 emit `@start` → 父页面校验登录/可抽 → `play()` 让转盘转 → 拿后端/mock 返回的 `prizeIndex` → `stop(index)` 停在指定格 → `@end` 弹提示。结果以服务端（或 mock）`prizeIndex` 为准，前端不做随机。
- **canvas 尺寸**：组件以 `size` prop（px）统一外层盒与画布尺寸，`ctx.scale(dpr)` 适配高清屏；`index.vue` 按屏宽计算 `wheelSize`。
- **mock 切换**：`index.vue` 里 `const useMock = true`。后端就绪后把 `useMock` 改为 `false`，即走 `getLuckyConfig`/`drawLucky`/`getLuckyRecords` 真实接口。

## 已知风险

- **canvas 指针/穿层**：中心"抽奖"按钮是叠加在 canvas 上的 `view`（`z-index:1`，canvas 不设 pointer-events）。若真机点不中，改用 `cover-view` 或调整层级。
- **转盘方向/格位对齐**：`stop(index)` 的格位索引与 `prizes[]` 的 `index` 对应关系需真机核对（0 起顺时针）。若停止格与预期索引偏差，调整 `rotateTo` 的 `base` 角度公式。
- **文字溢出**：奖品名过长会被截断/重叠，需真机确认 `fillText` 布局，必要时字体缩小或横向排布。
